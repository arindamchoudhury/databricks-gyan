# Lakeflow Spark Declarative Pipelines — 2026 Release Notes

> **Source:** [docs.databricks.com/aws/en/release-notes/dlt/2026](https://docs.databricks.com/aws/en/release-notes/dlt/2026)
> **Added:** 2026-06-11
> **Note:** Formerly "Delta Live Tables (DLT)" — renamed Lakeflow Spark Declarative Pipelines at DAIS 2025.

---

## April 2026 (April 5 – May 6)

**Runtime:** CURRENT: DBR 17.3 | PREVIEW: 18.1

**Standalone MVs/streaming tables on serverless (Beta)**
Create materialized views and streaming tables directly without a dedicated pipeline cluster.

**`REPLACE WHERE` flows (Beta)**
Incremental batch processing in pipelines and standalone streaming tables.

**SCD Type 2 optimization**
Null entries omitted from version maps — reduces storage.

**SQL editor skills for MVs and AUTO CDC**
Guided creation of materialized views and CDC pipelines directly from the SQL editor.

## March 2026 (February 26 – March 31)

**Runtime:** CURRENT: DBR 17.3.8 | PREVIEW: 18.1.0

**Serverless CPU vertical autoscaling**
Serverless pipelines dynamically adjust CPU resources based on utilization.

**Retain UC tables on pipeline delete**
New option to preserve associated tables when deleting a pipeline.

**New flow syntax for streaming tables**
Simplified declarative approach for creating streaming tables.

**Pipeline hooks (GA)**
Custom pre/post-update logic for job-triggered pipelines.

**Row filters and column masks preserved on table update**
Row filter and column mask configurations now survive pipeline table updates.

**CDC datetime rebase mode**
Handles legacy/modern calendar conversions in APPLY CHANGES.

**SQL in `foreachBatch`**
SQL statements now supported within `foreachBatch` operations.

**Forward references in sink registration**
Simplifies pipeline definitions that reference downstream sinks.

**Append-once flows validated in dry runs**
Catches configuration errors before execution.

## February 2026 (January 14 – February 25)

**Runtime:** CURRENT & PREVIEW: DBR 17.3

**Type widening (INT → LONG) without pipeline reset**
Schema evolution for Delta tables in pipelines — no reset required.
> **Learning path note (I3/I5):** Previously required a full pipeline reset to widen column types. Now handled automatically.

**SCD Type 1 with AUTO CDC**
Simpler CDC pattern — upserts only the latest value without maintaining full change history. Reduces storage for use cases that don't need full history.
> **Learning path note (I4):** New option alongside SCD Type 2. Choose Type 1 when you only need current state.

**Failed update reuses existing cluster**
Retries no longer spin up a new cluster — reduces retry latency and cost.

**Python pipeline errors carry SQL state codes**
Improved error diagnostics — easier to programmatically handle specific error types.

---

## January 2026 (November 14, 2025 – January 13, 2026)

**Runtime:** CURRENT & PREVIEW: DBR 17.3

**Data quality expectations in Unity Catalog (GA)**
Store and manage expectations directly in UC tables — centralized, version-controlled, auditable quality rules shareable across pipelines.
> **Learning path note (I3):** Major governance improvement — expectations no longer pipeline-local; they live in UC and can be shared.

**Continuous pipelines >7 days: graceful restart**
Restarts with explicit update cause (`INFRASTRUCTURE_MAINTENANCE`) instead of abrupt restart.

**Queued execution mode**
Multiple update requests auto-queued and executed sequentially — eliminates manual retry for frequent triggers.

**Multiple SCD Type 2 views from single CDC source**
One change data source can now materialize multiple Type 2 history views.

**Pipeline schedules in UC table properties**
Centralize pipeline config management alongside data definitions.

**MANAGE permissions auto-propagated**
Automatically propagated to materialized views and streaming tables in UC.

**SCD Type 2 duplicate coalescing**
Duplicate records with the same natural key automatically coalesced.

**Auto-drop inactive tables option**
Tables no longer in pipeline definition can be automatically dropped.

**Audit log enhancements**
Config changes, patches, and run-as identity changes now included in audit log.
