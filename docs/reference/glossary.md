# Glossary

Terms added as they are encountered. Source column shows where the definition came from.

| Term | Definition | Source |
|---|---|---|
| **Lakeflow Spark Declarative Pipelines** | The declarative ETL framework in Databricks (formerly Delta Live Tables / DLT); defines pipelines as SQL or Python table definitions with built-in data quality expectations | Databricks DAIS 2025 |
| **Apache Spark Declarative Pipelines** | The open-source declarative-pipelines project now upstream in Apache Spark. Lakeflow SDP extends and is interoperable with it, running on the Databricks Runtime — SDP is a Runtime-optimized superset, not a Databricks-only proprietary framework. | Databricks docs — [[ldp-overview]] |
| **Pipeline types (`pipeline_type`)** | Four underlying pipeline mechanisms behind the Jobs & Pipelines list: `WORKSPACE` (ETL — a defined SDP pipeline), `MANAGED_INGESTION` (Lakeflow Connect ingestion), `DBSQL` (MV/ST — a standalone pipeline), `DATABASE_TABLE_SYNC` (Database Table Sync — syncs a Lakehouse table into Lakebase). | Databricks docs — [[ldp-concepts-pipelines]] |
| **Lakeflow Pipelines Editor** | The IDE for SDP pipeline development: multi-file Python/SQL editor, pipeline assets browser, interactive dependency graph, data previews, execution insights, and selective (single-file/table) execution. Git-folder version control. | Databricks docs — [[ldp-concepts-pipelines]] |
| **Lakeflow Jobs** | Databricks orchestration system for multi-task workflows (formerly Databricks Workflows / Jobs) | Databricks 2025 |
| **Lakeflow Connect** | Managed ingestion connectors for ingesting from enterprise sources (databases, SaaS) into Databricks | Databricks 2025 |
| **Delta Lake** | Open-source storage format adding ACID transactions, versioning, and schema enforcement to Parquet files | delta.io |
| **Unity Catalog** | Databricks' centralized governance layer providing a three-level namespace (catalog.schema.table), fine-grained ACLs, and data lineage | Databricks docs |
| **Medallion Architecture** | A multi-hop data design pattern: Bronze (raw) → Silver (cleaned, validated) → Gold (business-ready aggregations) | Databricks docs |
| **Auto Loader** | Incremental file ingestion mechanism using cloudFiles source; detects new files in cloud storage using directory listing or file notification | Databricks docs |
| **APPLY CHANGES INTO** | SQL API for processing CDC (Change Data Capture) events into a target Delta table, supporting SCD Type 1 and Type 2 | Databricks docs |
| **Liquid Clustering** | Data layout strategy replacing partitioning and Z-order; dynamically clusters data based on specified columns for optimal skipping | Databricks docs (DBR 14+) |
| **Declarative Automation Bundles (DABs)** | Infrastructure-as-code framework for defining, deploying, and managing Databricks resources (jobs, pipelines, notebooks) as YAML + code. Formerly "Databricks Asset Bundles" — renamed March 2026; CLI commands unchanged. | Databricks docs |
| **OpenSharing** | Open protocol for sharing Delta Lake tables (and Iceberg tables) across organizations and platforms without copying data. Formerly "Delta Sharing" — renamed June 2026; same protocol, new name. opensharing.io | Databricks 2026 |
| **Photon** | Databricks' native C++ vectorized query engine replacing the JVM-based Spark SQL engine. Processes data in columnar batches (SIMD). Default-on on serverless compute and SQL warehouses. Transparent fallback to Spark for unsupported ops. No UDFs/RDD/Dataset APIs/stateful streaming. Required for Predictive IO and dynamic file pruning. | Databricks docs |
| **Data intelligence** | Databricks' framing for applying GenAI to understand the context and semantics of an organization's own data — learning its jargon, metrics, and business rules from metadata + usage to power self-serve insight and agents. | DIP-Dummies Ch 1 |
| **Agent Bricks** | Databricks framework to build, tune, evaluate, and deploy composable AI agent systems on enterprise data. Build via custom code, declarative NL prompts, or AI functions in SQL; built-in LLM judges; governed by Unity Catalog. | DIP-Dummies Ch 3–4 |
| **Lakebase** | Databricks' OLTP database "for the agentic era" — open-source Postgres foundation, compute/storage separation (ms-latency, high QPS, SLAs), instances launch in <1s, pay-per-compute. | DIP-Dummies Ch 3 |
| **SafeKeeper** | Lakebase's externalized WAL storage service; makes a Postgres commit durable by Paxos-replicating the log record across a quorum of SafeKeeper nodes, instead of a single local disk flush. | Databricks Blog — Lakebase/LTAP |
| **PageServer** | Lakebase's externalized data-files storage service; streams WAL from SafeKeeper and asynchronously materializes pages into cloud object storage — acts as a write-through cache and (for LTAP) transcodes rows into Parquet columnar form. | Databricks Blog — Lakebase/LTAP |
| **LTAP (Lake Transactional/Analytical Processing)** | Architecture unifying OLTP and OLAP at the storage layer: one durable copy of data in open columnar formats (Delta/Iceberg) that both Postgres and Lakehouse engines read — no CDC pipeline, no second copy. Contrast with HTAP, which unifies at the engine layer. | Databricks Blog — Lakebase/LTAP |
| **AI/BI Genie** | Conversational BI chatbot — translates natural-language questions into analytical SQL, responds with tables/visuals, governed by Unity Catalog, learns from feedback. | DIP-Dummies Ch 3 |
| **AI/BI Dashboards** | Self-serve dashboards where business users build datasets/reports/visuals via natural language or point-and-click, without waiting on technical BI teams. | DIP-Dummies Ch 3 |
| **Lakehouse Federation** | Query external sources (Snowflake, MySQL, Oracle, Hive) in place via Unity Catalog with zero copy; can expose data to tools like Salesforce, Palantir, SAP. | DIP-Dummies Ch 3 |
| **Model Context Protocol (MCP)** | Open standard giving agents a universal way to connect to data and tools (built-in, third-party, or custom proprietary APIs), removing per-framework custom connectors. | DIP-Dummies Ch 4 |
| **Databricks Apps** | Build/deploy secure data + AI apps directly on Databricks (no separate infra) — serverless compute, one-click Lakebase integration, UC governance, open Python/JS frameworks. | DIP-Dummies Ch 3–4 |
| **Databricks Assistant** | Context-aware AI assistant native in notebooks, SQL editor, and file editor; generates SQL from English, documents and debugs code using UC metadata. | DIP-Dummies Ch 3 |
| **Clean Rooms** | Secure, privacy-centric environment for collaborating on data with partners across clouds; powered by OpenSharing. | DIP-Dummies Ch 3 |
| **Data & AI maturity curve** | The journey from descriptive (DB/DW: what happened) → predictive (data lakes: what may happen) → prescriptive (best action) → GenAI on proprietary data with automated decisions. | Lakehouse-Dummies Ch 2 |
| **Decoupled storage & compute** | Lakehouse property of scaling storage and compute independently, so you pay for one without the other — enables near-limitless scale and many concurrent users. | Lakehouse-Dummies Ch 2 |
| **Vendor lock-in** | Dependence on one vendor such that switching is prohibitively costly (license fees, forced data copies, custom integration code). Open formats (Delta/Iceberg) avoid it. | Lakehouse-Dummies Ch 2 |
| **LLMOps** | Operating LLMs end-to-end — development, training, judging, and operationalizing with humans in the loop; the GenAI counterpart to MLOps. | Lakehouse-Dummies Ch 3 |
| **AI Gateway** | Databricks governance/control layer for AI models and agents — enforces access controls, rate limits, and guardrails, including models hosted outside Databricks. | Lakehouse-Dummies Ch 4 |
| **DBU** | Databricks Unit — the billing unit for compute usage on the platform | Databricks docs |
| **Control Plane / Data Plane** | Control plane: Databricks-managed services (UI, REST API, cluster manager). Data plane: customer's cloud account where compute runs and data lives | Databricks docs |
| **Compute plane** | Current term for where data is processed. **Serverless** compute plane runs in the Databricks account; **classic** compute plane runs in the customer's own cloud account (inside each workspace's virtual network). Replaces the older "data plane" wording. | Databricks docs — high-level-architecture |
| **Workspace storage** | Per-workspace storage holding **workspace file-system data** (notebooks, queries, dashboards, repos, libraries) and **workspace system data** (query/job results, notebook revisions, query plans, cluster logs). Separate from your own data objects (UC tables/volumes). Classic workspaces use 3 cloud buckets; deleting it makes the workspace unrecoverable. | Databricks docs — high-level-architecture |
| **Default storage** | Fully managed storage location used by **serverless** workspaces for internal workspace system data and Unity Catalog data assets. Serverless workspaces can also connect to the customer's own cloud storage. | Databricks docs — high-level-architecture |
| **`read_files()`** | SQL table-valued function for reading files from a Volume or path with inline format options (format, header, inferSchema). Automatically adds a `_rescued_data` column for rows that don't match the inferred schema. | DA-FREE M2-01 |
| **COPY INTO** | Idempotent, incremental SQL command for batch file ingestion into a Delta table. Tracks loaded file paths in the Delta log so re-runs load only new files. | DA-FREE M2-02 |
| **CTAS (CREATE TABLE AS SELECT)** | DDL pattern that creates a Delta table and populates it in one atomic statement. Used for one-shot full loads or Silver layer full refreshes. | DA-FREE M2-01 |
| **`CREATE OR REPLACE TABLE AS SELECT` (CRAS)** | CTAS variant that atomically drops and re-creates the table on each run. Resets Delta history. Common for Silver layer full refreshes. | DA-FREE M2-03 |
| **`INSERT OVERWRITE`** | Replaces all rows in a Delta table while keeping the table definition, properties, and version history. Adds a new Delta version on each run. Common for Gold layer refreshes. | DA-FREE M2-03 |
| **Managed table** | A table whose data lifecycle is owned by Unity Catalog. `DROP TABLE` removes both the catalog entry and the underlying files. Default for `CREATE TABLE` without `LOCATION`. | DA-FREE M2-01 |
| **External table** | A table that points to user-managed cloud storage (`LOCATION` clause). `DROP TABLE` removes the catalog entry but not the data files. | DA-FREE M2-01 |
| **Time travel** | Querying a past version of a Delta table via `VERSION AS OF n`, `@vN`, or `TIMESTAMP AS OF`. Requires old files not to have been vacuumed. | DA-FREE M2-01 |
| **`DESCRIBE DETAIL`** | SQL command that returns storage metadata for a Delta table: format, location, numFiles, sizeInBytes, partitionColumns. | DA-FREE M2-01 |
| **`DESCRIBE HISTORY`** | SQL command that returns the full version history of a Delta table: version number, timestamp, operation, operationMetrics. | DA-FREE M2-01 |
| **`IDENTIFIER` clause** | SQL clause that interprets a string expression as a named object (catalog, schema, table). Used with variables: `USE SCHEMA IDENTIFIER(DA.schema_name)`. | DA-FREE M2-01 |
| **Temp view** | A session-scoped view created with `CREATE [OR REPLACE] TEMP VIEW`. Not persisted to the Unity Catalog; disappears when the session ends. | DA-FREE M2-03 |
| **`_rescued_data`** | Column automatically added by `read_files()` to capture rows where a value couldn't be parsed into the inferred schema type. Non-null values indicate data quality issues. | DA-FREE M2-01 |
| **`_metadata`** | Struct column available on file-based DataFrames containing file-level metadata: `file_name`, `file_path`, `file_size`, `file_modification_time`. Replaces removed `input_file_name()` function (DBR 17.3+). | DA-FREE M2-02 |
| **Git folders** | Workspace folders connected to a Git provider (GitHub, GitLab, Bitbucket). Replaces the legacy Repos feature. Credentials configured in Settings → Developer → Linked Accounts. | DA-FREE M1 |
| **MWS (Multi-Workspace Storage)** | The Databricks account-level API tier for provisioning workspaces and configuring cloud infrastructure. All `databricks_mws_*` Terraform resources target the MWS endpoint (`accounts.cloud.databricks.com`). | Ch 29 — E7 |
| **`databricks_mws_workspaces`** | Terraform resource that creates a Databricks workspace on AWS or GCP by combining credentials, storage configuration, and network configuration. | Ch 29 — E7 |
| **`databricks_grants`** | Authoritative Terraform resource for Unity Catalog permissions — replaces *all* existing grants on a securable when applied. Use `databricks_grant` (per-principal) when other teams manage other principals. | Ch 29 — E7 |
| **Terragrunt** | Open-source wrapper around Terraform (by Gruntwork) that eliminates DRY violations: manages remote state backends, generates provider configurations, and orchestrates multi-unit deployments with dependency ordering. | Ch 29 — E7 |
| **Terragrunt unit** | A single Terraform root module with a `terragrunt.hcl` configuration file. The basic deployable entity in Terragrunt. Each unit has its own isolated state file. | Ch 29 — E7 |
| **Terragrunt stack** | A set of Terragrunt units defined in a `terragrunt.stack.hcl` file. `terragrunt run --all apply` deploys all units in dependency order, with optional parallelism. | Ch 29 — E7 |
| **Cross-account IAM role** | An AWS IAM role that Databricks assumes to create and manage resources (EC2 instances, security groups, ENIs) in the customer's VPC. Required for all AWS workspace deployments. | Ch 29 — E7 |
| **`time_sleep` (Terraform)** | Terraform resource from the `hashicorp/time` provider that introduces a deliberate wait between resource operations. Used after IAM policy attachment to absorb AWS propagation delay before Databricks validates the cross-account role. | Ch 29 — E7 |
| **Security Reference Architecture (SRA)** | Databricks' official opinionated Terraform template for a hardened production workspace deployment: Private Link VPC endpoints, customer-managed KMS keys, restrictive VPC endpoint policies, disabled legacy DBFS/access settings, audit log delivery, and the Security Analysis Tool. Available at `terraform-databricks-sra`. | Ch 29 — E7 |
| **Network Connectivity Configuration (NCC)** | Account-level Databricks object that controls network egress rules for serverless compute (SQL Warehouses, serverless jobs). Required for Private Link on serverless; without it, serverless clusters use Databricks-managed networking. | Ch 29 — E7 |
| **Security Analysis Tool (SAT)** | Databricks workflow that runs automated security posture checks against a workspace and produces a SQL dashboard scoring configuration across network security, identity, data protection, and governance. Deployed as part of the SRA. | Ch 29 — E7 |
| **Customer-Managed Keys (CMK)** | AWS KMS keys provided by the customer to encrypt Databricks data at rest. The SRA creates two: one for workspace storage (DBFS root + EBS volumes) and one for managed services (control-plane data: notebooks, secrets, query results). | Ch 29 — E7 |
| **Data lakehouse** | A unified architecture combining the low-cost, flexible storage of a data lake with the reliability, governance, and performance of a data warehouse. The Databricks Data Intelligence Platform is an AI-powered lakehouse built on Spark. | DCDE-SG Ch 1 |
| **Data Intelligence Platform (DIP)** | Databricks' current name for the lakehouse plus an AI layer that learns an organisation's semantics (table/column descriptions, metrics, jargon, usage, feedback) so search, BI, and agents understand the specific business. | DIP-Dummies Ch 1, 3 |
| **Two-tier architecture / two-tier tax** | The legacy pattern of a data lake feeding one or more data warehouses (plus specialised systems), requiring data to be copied between systems. The "tax" is the resulting staleness, latency, cost, and duplicated governance — the cost the lakehouse exists to eliminate. | What Is a Lakehouse? (2020) |
| **Schema-on-write vs schema-on-read** | Schema-on-write (data warehouses): data is structured/validated as it's loaded, optimised for BI consumption. Schema-on-read (data lakes): raw data is stored as-is and structure is applied at query time — agile but punts quality/governance downstream. | Lakehouse CIDR 2021 |
| **Transactional metadata layer** | A layer over object-store files that tracks which objects belong to a table at a given version (stored as a transaction log), giving raw files ACID transactions, versioning, and zero-copy operations. Delta Lake, Apache Iceberg, and Apache Hudi are the leading implementations. | Lakehouse CIDR 2021 |
| **Data independence** | Classic DBMS principle of hiding the physical storage format behind the query API so it can be changed freely. Lakehouses deliberately *give up* some of it — the open storage format becomes part of the public API — to allow fast direct access from ML/analytics engines. | Lakehouse CIDR 2021 |
| **TPC-DS** | Industry-standard decision-support benchmark (99 queries) used in the Lakehouse paper to show Delta Engine matching/beating four cloud warehouses on both runtime and cost at scale factor 30,000. | Lakehouse CIDR 2021 |
| **Data swamp** | A data lake that has degraded into an untrustworthy dumping ground — no schema enforcement, no quality controls, no governance — so its data can't be safely used. The failure mode a bare lake falls into without a table format like Delta. | Ch 1 — B1 |
| **Delta transaction log (`_delta_log`)** | The ordered, append-only record of every commit to a Delta table, stored in the `_delta_log/` directory beside the Parquet files. Readers consult it to see exactly which files form the table at a given version; it is the mechanism delivering ACID, schema enforcement, and time travel on object storage. | Ch 1 — B1 |
| **Databricks Runtime (DBR)** | A pre-configured VM image run by clusters, bundling a specific Apache Spark version plus Delta Lake, Scala, and system libraries. LTS releases get long-term support. Current: DBR 18 (Spark 4.1.0) / DBR 17.3 LTS (Spark 4.0.0). | DCDE-SG Ch 1 |
| **DBFS (Databricks File System)** | An abstraction layer that lets you interact with cloud object storage as if it were a local filesystem; files persist in the underlying cloud store (e.g., ADLS) beyond cluster life. ⚠️ DBFS root & mounts are deprecated (2026) — use Unity Catalog Volumes; `/databricks-datasets/` remains read-only accessible. | DCDE-SG Ch 1 |
| **All-purpose cluster** | An interactive cluster, manually created and managed, for development/EDA in notebooks. Costlier than job clusters; auto-termination enforces a 10-minute minimum runtime. | DCDE-SG Ch 1 |
| **Job cluster** | An ephemeral cluster auto-provisioned by the job scheduler for a single run and terminated on completion. Cheaper than all-purpose; recommended for production. | DCDE-SG Ch 1 |
| **Cluster pool** | A group of pre-warmed, idle VMs ready to attach to clusters, cutting start/autoscale time. Databricks doesn't bill idle pool instances, but the cloud provider does. | DCDE-SG Ch 1 |
| **Driver / Worker node** | A Spark cluster has one driver (orchestrates tasks, collects results) and N worker nodes (execute tasks in parallel). A single-node cluster runs both roles on one machine. | DCDE-SG Ch 1 |
| **Access mode** | A cluster security setting. Renamed in 2025: **Standard** (was "Shared", multi-user, SQL+Python) and **Dedicated** (was "Single user"; now also group-assignable, supports ML runtime/RDD/R/Scala). | DCDE-SG Ch 1 |
| **Lakeguard** | Databricks security layer for standard (multi-user) compute, serverless compute, and SQL warehouses. Enforces code isolation (Spark Connect + container sandboxing) and data filtering (prevents over-fetch leakage through row/column security). UDFs sandboxed with egress network isolation. Spark Connect defers name resolution to execution time — may change code behavior. | Databricks docs |
| **SQL warehouse** | SQL-optimised compute resource for Databricks SQL (query editor, Catalog Explorer, dashboards, BI tools). Distinct from classic compute clusters. Renamed from "SQL endpoint" in 2023. Serverless variant is recommended. Auto-starts when a query is run against it. Three types: Serverless (2–6 s startup, all features), Pro (~4 min, Photon+Predictive IO), Classic (~4 min, Photon only). | Databricks docs |
| **Predictive IO** | SQL warehouse feature that speeds up selective scan operations. Available on serverless and pro warehouses; not on classic. | Databricks docs |
| **Intelligent Workload Management (IWM)** | Serverless-only SQL warehouse feature. AI-powered prediction and dynamic resource management to handle variable query demand and queuing efficiently. | Databricks docs |
| **Starter Warehouse** | Small SQL warehouse automatically created in every Databricks workspace; enables immediate querying without admin setup. | Databricks docs |
| **Magic command** | A `%`-prefixed cell directive in Databricks notebooks: language magics (`%python`, `%sql`, `%scala`, `%r`), `%md` (Markdown + auto-TOC), `%run` (execute another notebook inline, importing its vars/functions), `%fs` (file-system ops). | DCDE-SG Ch 1 |
| **`dbutils` (Databricks Utilities)** | A programmatic utility API usable inside Python (e.g., `dbutils.fs.ls(...)`); richer than `%fs` because output can be captured in variables and combined with code logic. `dbutils.help()` lists modules. | DCDE-SG Ch 1 |
| **`display()`** | Databricks function that renders a list/DataFrame as an interactive table with CSV download and chart visualizations. Previews only a subset of large datasets. | DCDE-SG Ch 1 |
| **Autoscaling / Auto-termination** | Autoscaling dynamically adjusts worker count within a min/max range based on load. Auto-termination shuts an idle cluster down after a set period to avoid charges. Both default to on. | DCDE-SG Ch 1 |
| **Optimised autoscaling** | Premium-plan autoscaling that scales up in at most 2 events and can scale *down* even on non-idle compute (inspects shuffle file state). Scale-down window: 40 s for job compute, 150 s for all-purpose. | Databricks docs |
| **Standard autoscaling** | Standard-plan autoscaling: starts by adding 8 nodes, scales up exponentially; scales down when 90% of nodes are idle for 10 min and compute has been idle 30 s, starting with 1 node. | Databricks docs |
| **Flexible node types** | Instance type selection that falls back to alternative compatible instance types when the primary is unavailable, improving compute launch reliability. | Databricks docs |
| **Databricks widgets** (`dbutils.widgets`) | API for adding interactive input parameters (text, dropdown, combobox, multiselect) to notebooks and dashboards. Values are always strings. Supports parameter passing between notebooks (`%run $X="10"`) and to jobs. SQL uses `CREATE WIDGET` and parameter markers (`:param`). | Book Ch 01 — B1 |
| **ipywidgets** | Third-party Python library providing 30+ interactive UI controls (sliders, buttons, checkboxes, tabs). GA on DBR 13.0+; broken on DBR 15.0. Cannot pass parameters to jobs or between notebooks — use `dbutils.widgets` for that. Requires browser access to `databricks-dev-cloudfront.dev.databricks.com`. | Book Ch 01 — B1 |
| **Workspace files** | Source code files (`.py`, etc.) stored in the Databricks workspace and importable as Python modules. Requires DBR 11.3 LTS+. The recommended modularization approach over `%run`. Support Git version control and IDE debugging. | Book Ch 01 — B1 |
| **`%run`** | Notebook magic that executes another notebook inline, merging all its functions and variables into the calling notebook's scope. Must be the only content in its cell. Cannot import Python files — notebooks only. For parameter passing via `%run $X="10"`, classic compute only (not SQL warehouses). | Book Ch 01 — B1 |
| **`dbutils.notebook.run()`** | API that executes a notebook as a separate job (not inline). Returns the string value from `dbutils.notebook.exit()`. Arguments and return values are strings only; arguments must be ASCII. Available in Python and Scala only. Prefer Lakeflow Jobs for production scheduling. | Book Ch 01 — B1 |
| **Interactive debugger** | Built-in Python notebook debugger (DBR 14.3 LTS+ Standard; 13.3 LTS+ Dedicated; Serverless). Supports breakpoints, step-through, variable explorer, and debug console. Enable via Settings → Developer. Sessions auto-terminate after 30 min idle; console has 15-sec timeout. | Book Ch 01 — B1 |
| **SQL parameter markers** | `:param_name` syntax in SQL cells that binds a widget or named value to a SQL query position without string interpolation, preventing SQL injection. Requires DBR 15.2+. Use with `IDENTIFIER(:table)` for dynamic object names. | Book Ch 01 — B1 |
| **Fleet instance types** | AWS variable instance types (e.g. `m-fleet.xlarge`) that resolve to the best available same-size instance based on spot capacity and price at launch. No GPU support. | Databricks docs |
| **Autoscaling local storage** | Feature that auto-attaches EBS GP3 volumes to worker nodes when free disk runs low; limit 5 TB per instance including local storage. Volumes detach only when the instance is returned to AWS (never mid-run). | Databricks docs |
| **AWS Capacity Blocks** | Reserved compute capacity for a specific time window and AZ in AWS; claimed on Databricks by tagging compute with `X-Databricks-AwsCapacityBlockId`. Must be active before compute launch. | Databricks docs |
| **Local disk encryption** | Public Preview feature that encrypts shuffle data and ephemeral data on locally attached instance disks. Key is per-node, lives in memory, destroyed with the node. Enabled via Clusters API only. Adds performance overhead. | Databricks docs |
| **DBC file** | A Databricks Cloud archive bundling notebooks/folders for import/export between workspaces (folder ⋮ → Import). | DCDE-SG Ch 1 |
| **Interactive debugger (notebooks)** | Built-in visual debugger for Python notebooks: breakpoints (click the cell gutter; pauses before the line), step over/into/out, variable explorer, and a debug console. Enabled per-user via Settings → Developer. Steps into workspace-file functions only — not libraries or other notebooks. | Databricks docs |
| **Variable explorer** | Right-sidebar panel showing variable values while paused in the notebook debugger; **Inspect** runs debug-console code to reveal contents, with a search filter. | Databricks docs |
| **Debug console** | Bottom panel in the notebook debugger for running Python in the paused frame (Enter = single-line, Shift+Enter = multi-line). 15-second timeout; does not support `display()`. | Databricks docs |
| **Genie Code** | Databricks AI assistant that provides context-aware help, including debugging assistance during a notebook debug session. | Databricks docs |
| **Job (Spark)** | A unit of work triggered by a Spark action (e.g., `count()`, `write()`). One action = one Spark job; a single notebook cell may trigger multiple jobs. | Book Ch 02 — B2 |
| **Stage (Spark)** | A set of tasks within a Spark job that can run without a shuffle. Stage boundaries occur at wide transformations (joins, groupBy, distinct). | Book Ch 02 — B2 |
| **Task (Spark)** | The smallest unit of work in Spark — one task processes one partition on one CPU core. Task count = partition count. | Book Ch 02 — B2 |
| **Shuffle** | The Spark operation that redistributes data across partitions and executors; causes network transfer and disk I/O. The most expensive operation in Spark. | Book Ch 02 — B2 |
| **Spark Connect** | gRPC-based client-server protocol in Apache Spark that decouples the client (notebook/IDE) from the remote Spark driver. Used by Databricks serverless compute and Standard classic compute (via Lakeguard). Enables Versionless Spark and remote IDE connectivity. | Book Ch 02 — B2 |
| **Adaptive Query Execution (AQE)** | Spark runtime re-optimisation framework enabled by default on Databricks. After each shuffle exchange, uses actual row counts/sizes to: (1) convert sort-merge joins to broadcast, (2) coalesce small partitions, (3) split skewed partitions, (4) short-circuit empty relations. | Book Ch 02 — B2 |
| **Versionless Spark** | Databricks serverless compute feature that automatically upgrades the underlying Spark version between runs without user intervention. As of early 2026, over 2 billion workloads upgraded automatically. | Book Ch 02 — B2 |
| **Serverless compute (notebooks)** | Databricks-managed compute for interactive notebooks — no cluster to provision. Requires Unity Catalog; auto-selected when a new notebook runs without a pre-chosen resource. Default execution timeout: 2.5 hrs (9,000 s). No Spark UI; use query insights instead. | Databricks docs |
| **Query insights** | Post-execution performance panel for serverless notebook cells ("See performance"). Shows SQL/Python query metrics and links to the query profile visualization. All queries also appear in workspace Query History. Limitations: post-run profiles only, no Spark UI, no verbose metrics, no downloads. | Databricks docs |
| **Serverless overspend protection** | Automatic execution timeout (default 2.5 hrs) that cancels queries exceeding the limit. Configurable at workspace level (Settings → Compute → Serverless interactive) or per notebook via `spark.conf.set("spark.databricks.execution.timeout", <seconds>)`. | Databricks docs |
| **Serverless compute (jobs/workflows)** | Databricks-managed compute for Lakeflow Jobs — no cluster to configure; autoscaling and Photon enabled automatically. Supports notebook, Python script, dbt, Python wheel, and JAR task types. Default compute when creating jobs with supported task types. | Databricks docs |
| **Performance mode (serverless jobs)** | Governs startup speed and DBU consumption for a serverless job. **Standard**: lower DBU cost, 4–6 min startup latency. **Performance Optimized**: faster startup and execution for time-sensitive workloads. Both use the same SKU. | Databricks docs |
| **Auto-optimization (serverless jobs)** | Default-on feature that automatically tunes compute resources and retries failed tasks for serverless jobs. Disable via Retry Policy → uncheck "Enable serverless auto-optimization" for non-idempotent workloads. | Databricks docs |
| **Timeline view (Jobs UI)** | Per-run view in the Jobs UI listing individual tasks with their query statements and runtimes. Click a statement to open the full query profile. Equivalent to the Spark UI for serverless job debugging. | Databricks docs |
| **Serverless compute (pipelines)** | Databricks-managed compute for Lakeflow Spark Declarative Pipelines — no cluster config needed; Unity Catalog required. Enabling serverless removes any existing `clusters` config from the pipeline. Supports Standard and Performance Optimized modes. Recommended for all new pipeline development. | Databricks docs |
| **Stream pipelining** | Serverless-exclusive pipeline feature: microbatches run concurrently instead of sequentially (standard Spark Structured Streaming runs them sequentially), improving compute resource utilisation. Enabled by default on serverless pipelines. | Databricks docs |
| **Vertical autoscaling (pipelines)** | Serverless-exclusive feature that *adds to* Databricks enhanced autoscaling (horizontal) by automatically allocating the most cost-efficient instance types that can run the pipeline without out-of-memory errors. | Databricks docs |
| **Incremental refresh (pipelines)** | Serverless-exclusive feature: materialized views are refreshed incrementally whenever possible. Falls back to a full refresh if results cannot be computed incrementally. | Databricks docs |
| **Spark Connect** | Client-server architecture for Spark that decouples the driver from client code. The only supported API surface on serverless compute — RDD APIs are unavailable. Defers analysis and name resolution to execution time. | Databricks docs |
| **Managed table** | Table whose metadata **and** data files are owned by the metastore. Created with `CREATE TABLE` (no `LOCATION`). `DROP TABLE` deletes both metadata and the underlying data files. UC managed tables live in UC managed storage; default table type. | Book Ch 03 — B4 |
| **External table** | Table whose **metadata** is owned by the metastore but whose **data files** live at a user-specified `LOCATION` outside the database directory. `DROP TABLE` removes only the metadata; data files persist. In UC the `LOCATION` must fall under a registered external location. | Book Ch 03 — B4 |
| **Foreign table** | Read-only Databricks table representing data in an external system (Postgres, Snowflake, …) connected via Lakehouse Federation. Managed by the external catalog service, not Unity Catalog. One of the three primary UC table types. | Databricks docs |
| **Temporary table** | Session-scoped managed table that stores data for the duration of a Databricks session; auto-dropped at session end; no catalog/schema privilege needed. Distinct from a temporary *view*. | Databricks docs |
| **CTAS (`CREATE TABLE AS SELECT`)** | Creates and populates a table in one statement from a query; schema is inferred from the query result. Supports `COMMENT`, `PARTITIONED BY`, `LOCATION` options. | Book Ch 03 — B4 |
| **`CHECK` constraint** | Enforced Delta constraint resembling a `WHERE` clause; incoming rows must satisfy the condition. Validated against existing **and** new data — adding it fails if existing rows violate it. | Book Ch 03 — B4 |
| **Informational constraint (PK/FK)** | Unity Catalog `PRIMARY KEY` / `FOREIGN KEY` constraint that is declared but **not enforced** — used for query optimization and ER-diagram/lineage tooling, surfaced in `INFORMATION_SCHEMA.TABLE_CONSTRAINTS`. | Databricks docs |
| **Deep clone** | `CREATE TABLE … DEEP CLONE source` — copies both data and metadata into a standalone table; can be re-run with `CREATE OR REPLACE` to incrementally sync from source. Slow for large tables. | Book Ch 03 — B4 |
| **Shallow clone** | `CREATE TABLE … SHALLOW CLONE source` — copies only the transaction log (metadata + file references), no data movement. Fast; ideal for dev/test. UC: managed→managed / external→external only, no nesting. | Book Ch 03 — B4 |
| **Stored view** | View whose definition is persisted in the metastore; re-executes its SQL against source tables on every query. Accessible across sessions and clusters; dropped only by `DROP VIEW`. | Book Ch 03 — B4 |
| **Temporary view** | View bound to the current Spark session; auto-dropped when the session ends. Not tied to any database. Created with `CREATE TEMP VIEW`. | Book Ch 03 — B4 |
| **Global temporary view** | View tied to the cluster (not a single session), stored in the `global_temp` database and queried with that qualifier. Survives across sessions on the same running cluster. Legacy — **not supported on serverless compute** (Spark Connect). | Book Ch 03 — B4 |
| **`Trigger.AvailableNow()`** | Recommended streaming trigger for serverless compute. Processes all available data in micro-batches then stops — the only fully supported incremental streaming trigger on serverless (`ProcessingTime` and `Continuous` triggers raise `INFINITE_STREAMING_TRIGGER_NOT_SUPPORTED`). | Databricks docs |
| **Predictive optimization** | AI-driven automatic table maintenance for UC managed tables — runs `OPTIMIZE` (compaction + incremental clustering), `VACUUM` (delete unused files), and `ANALYZE` (stats for data skipping) without manual ops. On by default for accounts created ≥ Nov 11 2024; rolling out to existing accounts. | Databricks docs — B4 |
| **Catalog commits** | UC managed-table feature (`delta.feature.catalogManaged`, off by default) enabling multi-statement transactions across tables, faster planning via UC-served metadata, enforceable schema/constraint changes, and safe writes from external engines. | Databricks docs — B4 |
| **Transaction (multi-statement)** | Coordinates DML across multiple SQL statements and up to 100 tables as one atomic, ACID unit — all commit or all roll back. Requires UC managed tables with catalog commits. One transaction = one Delta log entry. Optimistic concurrency, conflicts detected at commit. | Databricks docs — B4 |
| **Non-interactive transaction** | `BEGIN ATOMIC … END;` compound statement; auto-commits on success, auto-rolls-back on error. Supports **row-level** concurrency. Recommended default; for fixed sequences and scheduled jobs. | Databricks docs — B4 |
| **Interactive transaction** | `BEGIN TRANSACTION; … COMMIT;`; manual commit/rollback, **table-level** concurrency. For conditional logic, validation/debugging, and JDBC/ODBC/Python clients. Rolls back after 10 min idle or 48 h total. | Databricks docs — B4 |
| **`UNDROP TABLE`** | Recovers an accidentally dropped UC managed table within the recovery period (default 7 days). Period is configurable per catalog/schema (0, or 7–30 days) via `RETAIN DROPPED TO`/`FOR`. After it ends, files are deleted from cloud storage within 48 hours. | Databricks docs — B4 |
| **Credential vending** | UC mechanism that issues temporary, scoped credentials to external engines (via Unity REST API / Iceberg REST Catalog), inheriting the requesting principal's privileges so governance is preserved on direct table access. | Databricks docs — B4 |
| **Compatibility Mode** | Lets external clients that don't support UC's open APIs read managed tables with any Delta Lake or Apache Iceberg client; the only sanctioned form of path-based access to managed tables. | Databricks docs — B4 |
| **Iceberg REST Catalog (IRC)** | Open API giving Apache Iceberg clients read/write/create access to managed Iceberg tables, plus read-only access to Delta tables with Iceberg reads enabled (UniForm). Supports credential vending. | Databricks docs — B4 |
| **`SET MANAGED` / `UNSET MANAGED`** | `ALTER TABLE` clauses that convert an external Delta table to a UC managed table in place (`SET`) and roll it back within 14 days (`UNSET`). Min downtime, retains history/permissions/views, redirects path-based access. Needs DBR 17.3 LTS+ / Serverless. | Databricks docs — B4 |
| **UniForm (Iceberg reads)** | Delta feature exposing a Delta table to Apache Iceberg clients by also writing Iceberg metadata, so one table is readable as both Delta and Iceberg. Conversion uses `SET MANAGED TRUNCATE UNIFORM HISTORY` when UniForm is enabled. | Databricks docs — B4 |
| **Path-based redirect** | Public Preview (DBR 18.1+) feature that auto-redirects path-based reads/writes against a converted table's old external location to the new managed location, so legacy path code keeps working. Backward-compat only; adds ~hundreds of ms overhead. | Databricks docs — B4 |
| **Managed storage location** | Cloud-storage location where UC stores data + metadata for managed tables and managed volumes. Set on metastore / catalog / schema (lower overrides higher); catalog-level recommended. Catalog/schema locations must sit inside an external location and be ≤150 chars; cannot overlap external tables/volumes. | Databricks docs — B1, B4 |
| **Storage Root vs Storage Location** | The `MANAGED LOCATION` you give UC is the **Storage Root**; UC appends a hashed `__unitystorage/...` subdir per object to guarantee uniqueness, and the resulting full path is the **Storage Location**. Lets the same root be reused across catalogs/schemas. | Databricks docs — B1 |
| **Disk cache (Delta/DBIO cache)** | Proprietary Databricks cache that copies remote Parquet (incl. Delta) onto worker local SSDs in a fast format, automatically on first read; auto-invalidates on file change. Distinct from Spark cache (in-memory, manual). Enable by choosing an SSD-backed worker type. Formerly "Delta cache"/"DBIO cache". | Databricks docs — A1 |
| **Dynamic file pruning (DFP)** | Runtime optimization that pushes a join filter from the small side into the large table's scan, skipping non-matching files before reading. Default-on; triggers when probe-side Delta table ≥10 GB and ≥10 files. DML (MERGE/UPDATE/DELETE) DFP requires Photon. Amplified by liquid clustering. | Databricks docs — A1 |
| **Low shuffle merge** | Optimized `MERGE` (default-on DBR 10.4 LTS+) that processes unmodified rows in a shuffle-free path and preserves their data layout (incl. liquid clustering/Z-order) best-effort, cutting shuffle and reducing the need to re-`OPTIMIZE` after merges. | Databricks docs — A1, I5 |
| **Cost-based optimizer (CBO)** | Spark SQL optimizer (default-on, `spark.sql.cbo.enabled`) that uses table + column statistics to pick better plans, esp. join order, for multi-join queries. Needs `ANALYZE TABLE … COMPUTE STATISTICS`; predictive optimization runs ANALYZE automatically on UC managed tables. | Databricks docs — A1 |
| **Range join optimization** | Speeds joins on point-in-interval/interval-overlap conditions by binning the value domain so only same-bin candidates are compared. Auto in Databricks SQL (samples for bin size); else tune via `/*+ RANGE_JOIN(rel, binSize) */` hint or `rangeJoin.binSize`. Cast numeric equality keys to STRING to avoid mis-binning. | Databricks docs — A1 |
| **Isolation level (WriteSerializable / Serializable)** | Delta's two isolation levels. `WriteSerializable` (default) allows more concurrency; `Serializable` guarantees read-serializability at lower concurrent-write throughput. Set via `delta.isolationLevel` table property — a metadata change that fails concurrent writes + breaks streaming reads. | Databricks docs — A1, B4 |
| **Attribute-based access control (ABAC)** | Unity Catalog access model granting access by attributes/tags on securable objects instead of enumerating per-object grants — a first-class UC access-control task alongside the hierarchical privilege model. | Databricks docs — I7 |
| **Data quality monitoring (UC)** | Unity Catalog governance feature: anomaly detection across all tables in a catalog/schema + statistical profiling of an individual table. Distinct from pipeline expectations (which only gate in-flight rows). | Databricks docs — I7, A6 |
| **Partition metadata logging** | Opt-in partition-discovery strategy for UC **external** tables (`partitionMetadataEnabled='true'`, DBR 13.3 LTS+). UC reads only registered partition metadata (Hive-metastore-style) instead of recursively listing the table location — faster reads, but auto-discovery is off so out-of-band writes need a manual repair. Non-Delta only (Parquet/ORC/CSV/Avro/JSON). | Databricks docs — B4 |
| **MSCK REPAIR TABLE** | SQL command to sync UC partition metadata with the actual Hive-style partition directories under an external table's `LOCATION`: `SYNC PARTITIONS` (add+remove), `ADD PARTITIONS`, `DROP PARTITIONS`. Also `… SYNC METADATA` to resync schema after out-of-band metadata edits. | Databricks docs — B4 |
